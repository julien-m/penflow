# Real runtime pilot

Run the isolated test application with `.venv/bin/python tests/runtime_pilot/run_pilot.py`. An existing consumer can supply `--project <root> --contract <canonical-contract.json>`; the contract must be inside that project. The runtime uses Python stdlib HTTP/SQLite, external Node.js and the external `playwright` package. Before snapshotting, it resolves Node from `PATH`, Playwright from the caller’s Node module search (including `NODE_PATH` and modules adjacent to the selected Node installation), and the matching Playwright-managed Chromium executable. Install these external prerequisites with `npm install playwright` and `npx playwright install chromium` in your runner environment. No tool or browser is downloaded by the runner.

Override installed paths with `--node`, `--playwright`, and `--browser`, or `PENFLOW_PILOT_NODE`, `PENFLOW_PILOT_PLAYWRIGHT`, and `PENFLOW_PILOT_BROWSER`; CLI flags take precedence. Playwright accepts a resolvable module name or package entrypoint path. Relative paths and `~` are resolved in the caller’s environment before the retained process starts. `--browser` also accepts an executable on `PATH` (including an external Chromium-compatible browser). Missing prerequisites stop with installation/override guidance before snapshot creation. No browser package is imported by Penflow core.

Read the [runner](run_pilot.py), [server](app.py), [served interface](index.html), and [browser adapter](capture.mjs). The runner snapshots and executes its own source under `.specs/testing/runtime-evidence/<invocation>/producer/`, records exact artifact hashes before starting and rechecks them before publishing its retained build manifest. It uses an ephemeral browser context and its own server/database; no personal browser profile or existing app is accessed.

The three default screens implement the native Pencil layout at the desktop capture viewport. Inter regular and semibold are served from the same immutable application snapshot; read the [pinned upstream provenance](font-sources.json) and [OFL license](inter-license.txt). Font files participate in the build identity. The [font observer](font_capture.mjs) waits for loaded FontFace entries, checks served bytes against the snapshot and records Chromium's actual glyph providers; fallback fonts block capture. No font download occurs during capture. Geometry is independently normalized from the observed DOM screen origin, while raw viewport rectangles and computed border/layout styles remain available. The checkout, details and receipt screenshots are original browser captures retained alongside their raw observations.

Nine real scenarios observe local amount editing, invalid input, save, duplicate submission, denied actor, explicit service failure, SQLite transaction failure, browser back, and window close. The browser records measured geometry, raw computed styles, DOM text/state, input validity, actual requests/responses and navigation; a rendered interactive control without a semantic annotation blocks capture. Roles come from native tags or supported ARIA roles, never the `data-role` hint. The server executes real SELECTs around each scenario; after save and duplicate submission it is restarted and rereads the stored payment in its new process. A separately executed SQLite reader independently verifies each state and reports its own true process identity. Invalid input and denied actor produce visible refusal before POST; the browser records absence of POST during the completed interaction and network-idle observation window. Client input validity is measured before submission, not inferred from a later result. Runtime-result guards are observed synchronously after the actual response and before UI mutation. The service failure is an explicit test-app mode, not a production outage simulation. The storage failure executes an actual invalid SQLite statement after an insert inside the same transaction, then independent reads prove rollback of that insert. Actor and failure mode are runner URL configuration, not product widgets or a production authentication system.

Outputs are retained, including failed invocations. `runtime-result.json` describes this bounded test application's assertions only; `certification: not-run` remains explicit. With `--contract`, the runner calls the official `verification_source_references` helper before/after execution, emits `actual-ui-tree.json` and provenance, and converts supported functional obligations under `outcome-observations/`. Each observation binds a closed `penflow-runtime-facts` envelope whose raw references identify both browser and storage captures. The C12 state index is derived from closed `penflow-runtime-ui-snapshot` witnesses, including static screens without invented actions or actors. Declared causal transitions also receive the existing C44 bundle and distinct receipts derived from real browser click events and measured pre/post state. Conversion reads requirements for IDs and selection, never for expected values to insert into observed facts. Unknown obligations or missing captures fail explicitly. Reruns archive previous outputs automatically under their retained invocation; a process lock serializes publication. No approved source, contract, or native design proof is changed by this runner.

Without a supplied contract, the manifest is intentionally unbound to a business contract and cannot close C51. Even with bound artifacts, the consumer must supply native design evidence and use the official C51 pipeline/revalidator to certify the exact implementation. These captures are neither native Pencil proof nor certification of an existing consumer application.

The producer trust boundary belongs to the caller: hashes identify retained bytes but do not independently establish that an arbitrary untrusted producer executed them. This runner's actual invocation and process transcript supply the bounded execution evidence. A caller must not accept a report-supplied manifest as independent build authority.

Run `.venv/bin/python tests/runtime_pilot/boundary_probes.py` for three separate real-browser negative probes: an unannotated rendered button blocks capture; a span claiming `data-role="button"` is observed as text; mutation of the executing HTML after capture begins blocks build-manifest publication. These external probes require the browser tooling and are deliberately separate from the core pytest suite. Read the [probe implementation](boundary_probes.py).

Run `.venv/bin/python tests/runtime_pilot/check_conversion.py --run <retained-invocation> --contract <contract.json> --output <new-directory-inside-capture-project>` to test conversion separately. It rechecks raw hashes, copies evidence for the test, validates typed facts/C12 and proves that poisoned expected values do not change measured facts. This test is explicitly historical conversion, never certification. Read the [conversion checker](check_conversion.py), [outcome converter](convert_observations.py), and [tree converter](convert_tree.py).
